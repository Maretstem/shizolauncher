# ShizoLauncher

Лаунчер Minecraft-сервера **SHIZOSTAN**. Ставит и обновляет сборку сервера одной кнопкой, умеет в лицензию, Ely.by и офлайн, держит сколько угодно своих экземпляров с модами с Modrinth.

Написан с нуля на Electron, **без единой runtime-зависимости**: протокол запуска Minecraft, загрузчик, авторизация и пинг сервера реализованы на стандартной библиотеке Node.

## Скачать

Последняя версия — на странице [Releases](https://github.com/Maretstem/shizolauncher/releases/latest): файл `ShizoLauncher Setup X.Y.Z.exe`.
Уже установленный лаунчер обновляется сам: при запуске наверху появляется кнопка «Обновление».

Установщик не подписан, поэтому Windows покажет окно SmartScreen — нажми «Подробнее» → «Выполнить в любом случае».

## Что умеет

| | |
|---|---|
| **Сборка сервера** | Сверяет версию с `pack.json` на хостинге, докачивает только изменившиеся файлы, удаляет убранные из сборки, проверяет SHA-1 каждого файла. Моды игрока, миры и его настройки не трогает. Без сети запускает уже установленную версию. |
| **Аккаунты** | Microsoft (device code flow), Ely.by (с двухфакторкой и authlib-injector — скины и вход на сервер), офлайн. Несколько аккаунтов, токены зашифрованы ключом ОС (DPAPI). |
| **Экземпляры** | Любая версия Minecraft, Vanilla / Fabric / Quilt. Свои память, Java и JVM-аргументы на экземпляр. |
| **Modrinth** | Поиск и установка модов, ресурспаков, шейдеров (зависимости подтягиваются сами), установка модпаков и импорт `.mrpack`. |
| **Java** | Нужная версия скачивается автоматически с серверов Mojang — игроку ничего ставить не надо. |
| **Сервер** | Онлайн и пинг прямо на главной (Server List Ping), автозаход на сервер при запуске сборки. |
| **Разработка** | Вкладка с постами админов: превью будущих обновлений, ивенты, картинки, GIF и видео. Посты публикуются из веб-панели сборки. |
| **Уведомления** | Обновления лаунчера и сборки, новости и ивенты сервера, посты о разработке — уведомлениями Windows. Каждый вид включается отдельно. |
| **Трей** | Автозапуск с Windows свёрнутым в трей: обновления сборки скачиваются заранее, уведомления приходят без открытого окна. |
| **Скин** | 3D-превью скина в меню аккаунта (Microsoft, Ely.by, свои серверы; офлайн — скин с Ely.by по нику). |
| **Прочее** | Консоль игры в реальном времени, «починка» файлов, отмена загрузок, работа через системный прокси. |

## Запуск

```bash
npm install
```
```bash
npm start
```

Тесты ядра (10 штук, включая установку/обновление сборки с локального сервера):

```bash
npm test
```

Проверка без окна — скачать версию и довести игру до главного меню:

```bash
npm run smoke
```

Установщик для Windows (появится в `release/`):

```bash
npm run dist
```

## Настройка под сервер — `launcher.config.json`

```json
{
  "serverName": "SHIZOSTAN",
  "packUrl": "https://example.com/pack/pack.json",
  "serverAddress": "play.example.com",
  "azureClientId": "",
  "links": { "discord": "https://discord.gg/...", "telegram": "https://t.me/...", "site": "" }
}
```

Заполни до сборки установщика — игрокам ничего настраивать не придётся. Те же поля можно переопределить в «Настройках» лаунчера.

### Как выложить сборку

1. Сложи содержимое `.minecraft` сборки в `моя-сборка/files/` (`mods/`, `config/`, …).
2. Сгенерируй манифест:
   ```bash
   node tools/make-pack.mjs моя-сборка --version 1.0.0 --mc 1.21.11 --loader fabric --loader-version 0.20.1 --changelog "Первая версия"
   ```
3. Залей папку `моя-сборка` целиком на любой статический хостинг (свой сервер, GitHub Pages, S3).
4. Адрес `pack.json` впиши в `packUrl`.

Обновление сборки: поменяй файлы, запусти ту же команду с новым `--version`, перезалей. Лаунчеры игроков увидят новую версию и докачают разницу. Файлы из `config/`, `options.txt` и `servers.dat` ставятся один раз и потом не перезаписываются — чтобы не сбрасывать игрокам их настройки.

### Вход через Microsoft

Mojang пускает к API только одобренные приложения, поэтому нужен свой Client ID:

1. [portal.azure.com](https://portal.azure.com) → App registrations → New registration, тип аккаунтов — *Personal Microsoft accounts only*.
2. Authentication → *Allow public client flows* → **Yes**.
3. Подай заявку на доступ к Minecraft API: <https://aka.ms/mce-reviewappid> (одобрение занимает несколько дней).
4. Application (client) ID впиши в `azureClientId`.

До одобрения лаунчер покажет понятную ошибку; Ely.by и офлайн работают сразу.

## Как устроено

```
src/main/core/      ядро — чистый Node, без Electron, покрыто тестами
  net.js            загрузки с пулом, докачка по SHA-1, безопасные пути
  minecraft.js      метаданные Mojang, правила, Fabric/Quilt, Java, аргументы запуска
  auth.js           Microsoft / Ely.by / офлайн
  pack.js           сборка сервера: версия, синхронизация
  modrinth.js       поиск, моды, модпаки
  instances.js      экземпляры и их содержимое
  ping.js           Server List Ping
src/main/main.js    окно, хранилище, IPC
src/main/preload.cjs единственный мост в окно: вызов по имени + 4 события
src/renderer/       интерфейс на чистом HTML/CSS/JS
```

Безопасность: окно в песочнице с `contextIsolation`, CSP без inline-скриптов, внешние строки попадают в DOM только как текст, все пути из манифестов проверяются на выход за папку игры, каждый скачанный файл сверяется по хешу, модпаки качаются только с разрешённых Modrinth хостов.

Данные лежат в `%APPDATA%\ShizostanLauncher` (отдельно от старого Shizolauncher).

## Ограничения

- Версии Minecraft до 1.7 запускаются без звука.
- Проверено на Windows 10; на Linux для модпаков и версий до 1.19 нужен `bsdtar`.

## Сборка SHIZOSTAN сейчас

Лежит в папке `../shizostan-pack`, опубликована через GitHub Pages: <https://maretstem.github.io/shizo-mods/pack.json> (репозиторий `Maretstem/shizo-mods`, сайт раздаётся из ветки `gh-pages`).

Выпустить обновление: поменяй моды в `shizostan-pack/files/mods`, затем

```bash
node tools/make-pack.mjs ../shizostan-pack --version 1.0.1 --changelog "Что изменилось"
```

и в папке `shizostan-pack` закоммить и отправь (`git push` обновляет сразу `main` и `gh-pages`). Через минуту-две лаунчеры игроков увидят новую версию.

## Выпуск новой версии

Релизы собирает GitHub, а не твой компьютер:

1. Подними `version` в `package.json`, например `1.2.2`, и отправь изменения.
2. Поставь тег с той же версией и отправь его:
   ```bash
   git tag -a v1.2.2 -m "Что нового в этой версии"
   ```
   ```bash
   git push origin v1.2.2
   ```
3. Через 5–10 минут [сборка](https://github.com/Maretstem/shizolauncher/actions) создаст релиз с установщиком, а лаунчеры игроков предложат обновиться. Текст тега станет описанием релиза.

Если тег не совпадает с версией в `package.json`, сборка остановится с ошибкой — иначе лаунчер предлагал бы обновление бесконечно.

## Обновление самого лаунчера

Лаунчер при запуске смотрит последний релиз в GitHub-репозитории из `launcher.config.json` → `updateRepo` (сейчас `Maretstem/shizolauncher`). Если версия релиза новее установленной, наверху появляется кнопка «Обновление X» — лаунчер сам скачает установщик, сверит контрольную сумму, установит и перезапустится.

Как выпустить новую версию:

1. Подними `version` в `package.json` (например, `1.2.1`) и собери установщик:
   ```bash
   npm run dist
   ```
2. На GitHub открой репозиторий → **Releases** → **Draft a new release**.
3. В поле тега напиши `v1.2.1` (та же версия, с буквой `v`), в описании — что нового: игроки увидят этот текст.
4. Перетащи в релиз файл `release/ShizoLauncher Setup 1.2.1.exe` и нажми **Publish release**.

Репозиторий должен быть публичным. Тег обязан совпадать с версией в `package.json`, иначе лаунчер будет предлагать обновление бесконечно.
